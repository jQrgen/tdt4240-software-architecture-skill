# Credits and licence

## Primary literature

The skill's theory rests on the following works. It paraphrases their concepts and does not reproduce
their text. URLs are given only where they are well established.

- Len Bass, Paul Clements and Rick Kazman. *Software Architecture in Practice*, 4th ed. Addison-Wesley, 2021
  (the backbone; chapter numbers in the skill refer to this edition unless stated). 3rd ed., 2013, for
  chapter cross-references.
- Paul Clements et al. *Documenting Software Architectures: Views and Beyond*, 2nd ed. Addison-Wesley, 2010.
- Philippe Kruchten. "The 4+1 View Model of Architecture". *IEEE Software* 12(6), 1995.
- ISO/IEC/IEEE 42010:2022, *Software, systems and enterprise — Architecture description*, and its
  predecessors ISO/IEC/IEEE 42010:2011 and IEEE Std 1471-2000.
- Rick Kazman, Mark Klein and Paul Clements. *ATAM: Method for Architecture Evaluation*. Technical Report
  CMU/SEI-2000-TR-004, Software Engineering Institute, Carnegie Mellon University, 2000.
- Humberto Cervantes and Rick Kazman. *Designing Software Architectures: A Practical Approach*.
  Addison-Wesley, 2016 (Attribute-Driven Design 3.0).
- Neal Ford, Rebecca Parsons and Patrick Kua. *Building Evolutionary Architectures*. O'Reilly, 2017
  (fitness functions).
- Michael Nygard. "Documenting Architecture Decisions", 2011:
  <https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions>.
- Simon Brown. The C4 model for visualising software architecture: <https://c4model.com/>.
- Gernot Starke and Peter Hruschka. arc42 architecture documentation template: <https://arc42.org/>.
- David L. Parnas. "On the Criteria To Be Used in Decomposing Systems into Modules". *Communications of the
  ACM* 15(12), 1972 (information hiding).
- Robert C. Martin. Package design principles and metrics (afferent/efferent coupling, instability,
  abstractness, distance from the main sequence), in *Agile Software Development: Principles, Patterns, and
  Practices*. Prentice Hall, 2002.
- Adam Tornhill. *Your Code as a Crime Scene*. Pragmatic Bookshelf, 2015 (hotspots, change coupling).
- Gail C. Murphy, David Notkin and Kevin Sullivan. "Software Reflexion Models: Bridging the Gap between
  Source and High-Level Models". ACM SIGSOFT Symposium on the Foundations of Software Engineering, 1995.
- James O. Coplien. "Software Design Patterns: Common Questions and Answers". In *The Patterns Handbook*,
  Cambridge University Press, 1998.
- Erich Gamma, Richard Helm, Ralph Johnson and John Vlissides. *Design Patterns*. Addison-Wesley, 1994.
- Andrew Rollings and Dave Morris. *Game Architecture and Design: A New Edition*. New Riders, 2004.
- Robert Nystrom. *Game Programming Patterns*. Genever Benning, 2014: <https://gameprogrammingpatterns.com/>.

Tool names (ArchUnit, Konsist, dependency-cruiser, eslint-plugin-boundaries, import-linter, go-arch-lint,
jdeps, madge, pydeps, Structurizr and others) belong to their respective projects.

## Wally wallet architecture description

The architecture-description approach (AS-IS/TO-BE discipline, view map, ranked quality goals with a
conflict rule, intended-vs-actual layering, embodied vs proposed ADRs, and executable architecture rules) is
adapted, in paraphrase, from the Wally wallet architecture description:
<https://gitlab.com/wallywallet/wallet/-/merge_requests/853>.

- Version used: "Wally Personal Wallet — Software Architecture Description", draft for review, baseline
  `wallyApp = 3.30.04`, as proposed in MR !853.
